# PRD.md — 요금제 추천·구독 서비스

색·글자·간격·컴포넌트 같은 비주얼 규칙은 이 문서에 쓰지 않는다. 모든 비주얼 규칙은 **Design.md를 따른다.**

용어: 화면에 보이는 금액 이름은 "매달 내는 금액"으로 통일한다. "월 요금"(컴포넌트 설명), "월 납부 금액"(screens.md)은 같은 값이다.

---

## 1. 목적

### 한 줄 정의

요금제 추천·구독은 **월말 전에 데이터가 떨어지는 고객**이 **데이터량·속도 제한 여부·실제 월 납부액을 비교해 맞는 요금제를 골라** **통신사 모바일 웹을 벗어나지 않고 바로 신청**하는 모바일 웹 서비스다.

### 해결할 문제

1. 출퇴근길에 영상을 보는 고객은 매달 20일쯤 데이터가 다 떨어진다.
2. 고객은 통신사 앱·홈페이지의 요금제 페이지를 먼저 열지만, 20개가 넘는 요금제 목록에서 몇 개만 눌러보다가 포털 검색("데이터 무제한 요금제 추천")이나 커뮤니티 후기로 이탈하고, 정보가 너무 많아 결국 변경을 포기한다.
3. 고객은 두 가지를 판단하지 못한다.
   - "무제한"이라는 이름만으로는 기본 데이터 소진 후 속도가 제한되는 요금제인지, 속도 제한이 없는 요금제인지 구분할 수 없다. ("무제한이라면서 왜 느려져요?")
   - 정가·할인가·프로모션가가 함께 표시되어 매달 실제로 내는 금액과 24개월 할인 종료 후 금액을 알 수 없다. ("그래서 제가 매달 실제로 내는 돈이 얼마예요?")

---

## 2. 대상 사용자

### 유저 스토리

- **US1.** 출퇴근길에 영상을 보는 고객으로서, 월말까지 데이터를 쓰기 위해 데이터량을 기준으로 요금제를 비교하고 싶다.
- **US2.** 20개가 넘는 요금제 앞에서 선택이 어려운 고객으로서, 비교할 후보를 줄이기 위해 내 상황에 맞는 요금제만 추려 보고 싶다.
- **US3.** "무제한" 요금제를 보는 고객으로서, 월말에 속도가 느려지지 않기 위해 기본 데이터 소진 후 속도 제한이 있는지 확인하고 싶다.
- **US4.** 여러 가격이 함께 적힌 요금제를 보는 고객으로서, 실제 부담을 알기 위해 매달 내는 금액과 24개월 할인 종료 후 금액을 확인하고 싶다.
- **US5.** 요금제를 고른 고객으로서, 포털이나 커뮤니티로 나가지 않고 요금제를 바꾸기 위해 이 서비스 안에서 바로 신청하고 싶다.

### 사용자 상황 (도메인 스토리 요약)

출퇴근길에 영상을 보는 고객 A는 이번 달에도 20일쯤 데이터가 다 떨어졌다. A는 통신사 앱의 요금제 페이지를 열었지만 20개가 넘는 요금제 중 몇 개만 눌러보았다. "무제한" 요금제가 소진 후 속도 제한이 있는지 이름만으로 알 수 없었고, 정가·할인가·프로모션가가 함께 적혀 있어 매달 내는 금액과 24개월 할인 종료 후 금액도 알 수 없었다. A는 포털 검색과 커뮤니티 후기를 찾아보았지만 정보가 너무 많아 요금제 변경을 포기했다.

## 3. 화면 목록

지켜야 할 것: ① 화면 4개(3~6개 범위) ② "신청(저장)" 흐름 1개 포함(구독 신청 → 신청 완료) ③ 샘플 라이브러리 컴포넌트와 토큰으로만 구성(Design.md를 따른다)

BottomCTA Layout: 요금제 상세는 `price`, 구독 신청은 `double`, 신청 완료는 `single`을 쓴다.

### 화면 구조

| 순서 | 화면 이름 | 라우트 | 한 줄 역할 | 해결하는 유저 스토리 |
|---|---|---|---|---|
| 1 | 요금제 목록 | `/plans` | 요금제별 데이터량·소진 후 속도·매달 내는 금액을 한 카드에 표시해 후보를 고르게 한다 | US1, US2, US3, US4 |
| 2 | 요금제 상세 | `/plans/[id]` | 선택한 요금제의 매달 내는 금액, 할인 종료 후 금액, 소진 후 속도를 확인하고 신청으로 넘어가게 한다 | US3, US4, US5 |
| 3 | 구독 신청 | `/apply` | 신청 정보를 입력받아 구독 신청을 저장한다 | US4, US5 |
| 4 | 신청 완료 | `/complete` | 저장된 신청 내역을 표시한다 | US5 |

### 주요 흐름

```
요금제 목록 (/plans) → 요금제 상세 (/plans/[id]) → 구독 신청 (/apply) → 신청 완료 (/complete)
```

되돌아가는 흐름:

- 요금제 상세 → 뒤로(icon/arrowLeft) → 요금제 목록 (`/plans`)
- 구독 신청 → 뒤로(icon/arrowLeft)·취소 → 요금제 상세 (`/plans/[id]`)
- 신청 완료 → 뒤로(icon/arrowLeft) → 요금제 목록 (`/plans`)
- 신청 완료 → '요금제 더 보기' → 요금제 목록 (`/plans`)

예외 흐름:

- 요금제 id는 URL로 전달한다: 구독 신청은 `/apply?plan=[id]`, 신청 완료는 `/complete?id=[신청 번호]`. 새로고침해도 같은 화면이 유지된다.
- `/plans/[id]`의 id가 p01~p04가 아니면 `/plans`로 이동한다(기록을 남기지 않는 교체 이동).
- `/apply`의 plan 값이 없거나 p01~p04가 아니면 `/plans`로 이동한다. 새로고침하면 입력값은 비워진다.
- `/complete`의 신청 번호가 없거나 저장된 Subscription에 없으면 `/plans`로 이동한다.
- 저장에 성공하면 `/apply`를 `/complete`로 교체해 이동한다. 완료 화면에서 브라우저 뒤로가기를 눌러도 신청 입력 화면이 다시 나오지 않는다.

## 4. 화면별 기능

### 4-1. 요금제 목록 (`/plans`)

필수 기능:

0. **헤더 (Header Type=root + Logo)**
   - 표시 항목: 화면 제목 "요금제"와 U+ 로고
1. **요금제 카드 (Card/Plan)** — US1, US3, US4
   - 표시 항목: 요금제 이름 · 한 줄 설명 · 기본 데이터량 · 소진 후 속도("소진 후 ○Mbps로 제한" 또는 "속도 제한 없음") · 매달 내는 금액 1개 · 할인 종료 후 금액("25개월째부터 ○원") · '자세히' 버튼
   - Card/Plan의 `Original`(정가)은 항상 끈다. `Promo`는 "24개월 할인" 표시가 있을 때만 켠다.
   - 기본 상태: 요금제 데이터(아래 표)의 p01~p04 4개 카드를 모두 표시한다. 기본 정렬은 매달 내는 금액이 낮은 순(p01 → p04)이다.
   - 할인이 없는 요금제는 할인 종료 후 금액 줄을 표시하지 않는다.
   - 정가·할인가·프로모션가를 한 카드에 나란히 표시하지 않는다.
2. **요금제 필터 (FilterChip)** — US2
   - 표시 항목: 단일 선택 칩 4개 — '전체' / '50GB 이하'(p01, p02) / '100GB 이상'(p03, p04) / '속도 제한 없음'(p04). 어떤 칩을 골라도 결과가 비지 않는다.
   - 기본 상태: '전체' 칩이 선택되어 있고 4개 카드가 모두 표시된다.
   - 동작: 칩을 누르면 조건에 맞는 카드만 남고, 선택한 칩이 선택 상태로 바뀐다. '전체'를 누르면 4개 카드로 돌아간다.
3. **추천 표시 (Tag)** — US2
   - 표시 항목: 추천 Tag
   - 기본 상태: p02(데일리 50GB) 카드 1개에만 표시한다. 추천 기준은 월말까지 출퇴근길 영상 시청을 원하는 고객(US1)에게 맞는 데이터량이다.
4. **할인 프로모션 표시 (Chip)** — US4
   - 표시 항목: "24개월 할인" 문구
   - 기본 상태: 24개월 할인이 있는 요금제 카드에만 표시한다.
5. **상세 이동 ('자세히' Button)** — US5
   - 동작: 누르면 해당 요금제의 요금제 상세(`/plans/[id]`)로 이동한다.

로딩·빈·에러 상태: 이번 범위 밖이다(8장 참고). 잘못된 id·직접 진입은 "예외 흐름"의 이동 규칙으로 처리한다.

### 4-2. 요금제 상세 (`/plans/[id]`)

필수 기능:

1. **헤더 (Header + icon/arrowLeft)**
   - 표시 항목: 요금제 이름, 한 줄 설명(요금제 이름 아래), 뒤로 아이콘
   - 동작: 뒤로 아이콘을 누르면 요금제 목록(`/plans`)으로 이동한다.
2. **월 요금 (Card/Price)** — US4
   - 표시 항목: "매달 내는 금액" 1개(할인 적용 금액), 그 아래 "25개월째부터 ○원"(할인 종료 후 금액)
   - 기본 상태: 할인이 없는 요금제는 매달 내는 금액만 표시하고 할인 종료 후 줄은 표시하지 않는다.
   - 정가·할인가·프로모션가 3개를 함께 표시하지 않는다.
3. **기본 제공 항목 (List/Row)** — US1, US3
   - 표시 항목: 기본 데이터량, 소진 후 속도("소진 후 ○Mbps로 제한" 또는 "속도 제한 없음")
   - 통화·문자 등 그 밖의 행은 표시하지 않는다. 위 2행만 표시한다.
4. **추천 표시 (Tag)**
   - 기본 상태: 목록에서 추천 Tag가 붙은 요금제일 때만 표시한다.
5. **포함 혜택 (OptionItem)**
   - 표시 항목: 혜택 내용이 확정될 때까지 OptionItem 영역 전체(제목 포함)를 표시하지 않는다. (인터뷰에서 혜택 내용이 나오지 않음)
6. **신청 영역 (BottomCTA + '구독 신청하기' Button)** — US5
   - 표시 항목: 매달 내는 금액, '구독 신청하기' 버튼
   - 동작: 버튼을 누르면 선택한 요금제 id를 가지고 구독 신청(`/apply?plan=[id]`)으로 이동한다.

로딩·빈·에러 상태: 이번 범위 밖이다(8장 참고). 잘못된 id·직접 진입은 "예외 흐름"의 이동 규칙으로 처리한다.

### 4-3. 구독 신청 (`/apply`)

필수 기능:

1. **헤더 (Header + icon/arrowLeft)**
   - 동작: 뒤로 아이콘을 누르면 요금제 상세(`/plans/[id]`)로 이동한다. 입력값은 유지하지 않는다(개인정보를 남기지 않기 위함).
2. **선택한 요금제 요약 (List/Row)** — US4
   - 표시 항목: 요금제 이름, 매달 내는 금액, 할인 종료 후 금액(할인 있는 요금제만)
3. **신청 정보 입력 (Input)** — US5
   - 표시 항목: 이름 입력란, 휴대폰 번호 입력란
   - 기본 상태: 두 입력란 모두 비어 있다.
4. **개인정보 수집·이용 동의 (Checkbox)** — US5
   - 표시 문구: "[필수] 개인정보 수집·이용에 동의합니다. 수집 항목: 이름, 휴대폰 번호 / 이용 목적: 구독 신청 접수와 신청 내역 표시 / 보관 기간: 브라우저 탭을 닫을 때까지(탭을 닫으면 삭제)"
   - 기본 상태: 체크되지 않은 상태
5. **취소·신청하기 (BottomCTA double + '취소' Secondary Button + '신청하기' Primary Button)** — US5
   - 취소: 누르면 입력값을 버리고 요금제 상세(`/plans/[id]`)로 이동한다.
   - 입력 규칙: 이름은 앞뒤 공백을 제거한 뒤 1~20자이며 공백만 입력할 수 없다. 휴대폰 번호는 숫자만 입력할 수 있고(숫자 외 문자는 입력되지 않으며, 붙여넣기 시 숫자만 남긴다) 010으로 시작하는 11자리여야 한다. 검증은 입력란에서 포커스가 벗어날 때 한다.
   - 기본 상태: 이름 입력 규칙, 휴대폰 번호 입력 규칙, 동의 체크 중 하나라도 충족하지 않으면 '신청하기' 버튼이 비활성(Disabled) 상태다.
   - 동작: 세 조건을 모두 충족하면 버튼이 활성화된다. 누르면 Subscription 1건을 저장하고 신청 완료(`/complete?id=[신청 번호]`)로 이동한다.
   - 저장 중에는 버튼을 비활성(Disabled)으로 바꿔 다시 누를 수 없게 하며, 한 번의 신청은 Subscription 1건만 저장한다.
   - 저장에 실패하면 입력한 이름·휴대폰 번호·동의 체크를 그대로 유지하고, 오류 문구를 표시하고, 버튼을 다시 활성화한다. 다시 누르면 오류 문구를 지우고 저장을 재시도한다.

오류 상황과 안내 문구:

| 상황 | 안내 문구 | 표시 위치 |
|---|---|---|
| 이름 입력란을 비우거나 공백만 입력한 채 다음 입력란으로 이동 | 이름을 입력해 주세요. | 이름 입력란 아래 |
| 휴대폰 번호가 010으로 시작하는 숫자 11자리가 아닌 채 다음 입력란으로 이동 | 휴대폰 번호는 010으로 시작하는 숫자 11자리로 입력해 주세요. | 휴대폰 번호 입력란 아래 |
| 동의를 체크했다가 해제함 (버튼은 비활성 상태 유지) | 개인정보 수집·이용에 동의해야 신청할 수 있어요. | 동의 항목 아래 |
| 저장 실패 | 신청을 저장하지 못했어요. 다시 시도해 주세요. | 신청하기 버튼 위 |

### 4-4. 신청 완료 (`/complete`)

필수 기능:

1. **완료 표시 (icon/doneMark)** — US5
   - 표시 항목: 완료 아이콘, "구독 신청이 완료됐어요" 문구
2. **신청 내역 (List/Row)** — US5
   - 표시 항목: 신청 번호, 요금제 이름, 매달 내는 금액, 신청 일시, 신청자 이름
   - 기본 상태: 방금 저장한 Subscription 값으로 채운다.
3. **'요금제 더 보기' (BottomCTA + Button)**
   - 동작: 요금제 목록(`/plans`)으로 이동한다.
4. **뒤로 아이콘 (icon/arrowLeft)**
   - 동작: 요금제 목록(`/plans`)으로 이동한다.

로딩·빈·에러 상태: 이번 범위 밖이다(8장 참고). 잘못된 신청 번호·직접 진입은 "예외 흐름"의 이동 규칙으로 처리한다.

### 요금제 데이터 (실습용 가상 데이터)

인터뷰의 고객 상황(월말 전 데이터 소진, "무제한" 이름 혼동, 24개월 할인 후 금액 인상)을 재현하도록 구성했다. 실제 통신사 요금제가 아니다.

|---|---|---|---|---|---|---|
| p01 | 슬림 10GB | 39,000원 | 10GB | 1Mbps로 제한 | 할인 없음 | 출퇴근 영상 시청이 적은 고객용 기본 요금제 |
| p02 | 데일리 50GB | 52,000원 | 50GB | 1Mbps로 제한 | 할인 없음 | 출퇴근길 영상을 월말까지 보고 싶은 고객용 |
| p03 | 무제한 라이트 | 59,000원 (24개월 할인) | 기본 100GB | 5Mbps로 제한 | 25개월째부터 69,000원 | 이름은 무제한이지만 기본 데이터 소진 후 속도가 제한됨 |
| p04 | 무제한 프리 | 75,000원 | 무제한 | 속도 제한 없음 | 할인 없음 | 데이터를 다 써도 속도 제한이 없는 요금제 |

### 어기면 안 되는 것 (O/X 판정 규칙)

1. '전체' 칩이 선택된 상태의 요금제 목록에 요금제 카드가 정확히 4개(p01~p04) 있다.
2. 추천 Tag는 요금제 목록에서 p02 카드 1개에만 있다. 필터로 p02가 제외되면 Tag는 0개이고, 어떤 상태에서도 2개 이상 표시되지 않는다.
3. 요금제 카드와 요금제 상세에는 금액이 "매달 내는 금액" 1개와 "할인 종료 후 금액" 최대 1개만 있다. 정가·할인가·프로모션가 3개가 함께 표시되지 않는다.
4. 할인 종료 후 금액은 할인 기간(discount_months)이 있는 요금제(현재 p03)에만 있다.
5. 모든 요금제(p01~p04)의 카드와 상세에는 "소진 후 ○Mbps로 제한" 또는 "속도 제한 없음" 중 하나가 있다.
6. 구독 신청 화면에서 이름이 공백을 제외하고 비어 있거나, 휴대폰 번호가 010으로 시작하는 숫자 11자리가 아니거나, 동의가 체크되지 않으면 '신청하기' 버튼이 눌리지 않는다.
7. 신청 완료 화면의 요금제 이름과 매달 내는 금액이 구독 신청 화면에서 선택한 요금제와 같다.

## 5. 데이터

```yaml
Subscription:          # 구독 신청 1건
  id:                  string   # 신청 번호. 저장 시 생성
  name:                string   # 신청자 이름. 빈 값 불가
  phone:               string   # 휴대폰 번호. 010으로 시작하는 숫자 11자리
  plan_id:             string   # 요금제 id (p01 | p02 | p03 | p04)
  monthly_price:       number   # 신청 시점의 매달 내는 금액(원)
  agreed_privacy:      boolean  # 개인정보 수집·이용 동의. true일 때만 저장
  created_at:          datetime # 신청 일시. 저장 시 생성

Plan:                  # 요금제 (4장 요금제 데이터 표와 같은 값)
  id:                  string   # p01 ~ p04
  name:                string
  monthly_price:       number   # 매달 내는 금액(원)
  data:                string   # "10GB" | "50GB" | "기본 100GB" | "무제한"
  throttle_after:      string | null  # 소진 후 제한 속도(예: "5Mbps"). 제한 없으면 null
  price_after_discount: number | null # 할인 종료 후 월 요금. 할인 없으면 null
  discount_months:     number | null  # 할인 기간(개월). 할인 없으면 null
  description:         string   # 한 줄 설명
  recommended:         boolean  # 추천 Tag 표시 여부. p02만 true
```

저장 위치: 브라우저 sessionStorage에 저장하며 서버로 전송하지 않는다. 신청 완료 화면의 새로고침을 지원하기 위해 탭이 열려 있는 동안 유지하고, 탭을 닫으면 삭제한다.

휴대폰 번호는 어떤 화면에도 표시하지 않는다. 신청 완료 화면에는 신청자 이름만 표시한다.

표시 규칙:

- 소진 후 속도: throttle_after가 있으면 "소진 후 {값}로 제한", null이면 "속도 제한 없음".
- 할인 종료 후 금액: price_after_discount가 있으면 "{discount_months + 1}개월째부터 {금액}", null이면 줄을 표시하지 않는다.
- 금액: 천 단위 쉼표와 "원"을 붙인다. 예) 59,000원
- 신청 일시: "YYYY.MM.DD HH:mm"(24시간, 한국 시간).
- 신청 번호: "S" + 신청일 6자리(YYMMDD) + 임의 숫자 4자리. 같은 번호가 이미 저장돼 있으면 다시 생성한다.
- 한 줄 설명(description): 요금제 목록 카드와 요금제 상세 요금제 이름 아래에 표시한다.

## 6. 성공 기준

| 지표 | 목표 | 측정 방법 |
|---|---|---|
| 요금제 목록 방문 대비 요금제 상세 진입률 | 50% 이상 | `/plans` 진입 수와 '자세히' 클릭 수를 이벤트 로그로 집계 |
| 요금제 상세 진입 대비 신청 완료율 | 20% 이상 | `/plans/[id]` 진입 수 대비 `/complete` 도달 수 |
| 신청 화면 저장 실패율 | 1% 미만 | 저장 실패 문구 노출 수 / 신청하기 클릭 수 |

측정 기간은 출시 후 4주로 한다.
